Разбери файл `$ARGUMENTS` (если путь не указан — спроси; `debug/` обычно лежит на сервере, пользователь копирует файл вручную).

1. Прочитай заголовочные комментарии, которые пишет `p.py` (`Iteration`, `Timestamp`, `Type`, `Content Length`) и размер файла.
2. Определи тип ответа по признакам:
   - **Incapsula-заглушка**: маленький размер (единицы КБ), `_Incapsula_Resource`, `incap_ses`/`visid_incap`, iframe на `/_Incapsula_Resource?...`, `Request unsuccessful. Incapsula incident ID`.
   - **Капча/челлендж**: hCaptcha/reCAPTCHA, `challenge`, JS, который ставит cookie и перезагружает страницу.
   - **Нормальная страница**: есть `DisconSchedule.fact` (см. навык `dtek-schedule`) — проверь, что JSON парсится, и назови `fact.update`.
   - **Нормальная страница без графика / обрезанная**: есть разметка ДТЕК, но нет `DisconSchedule`.
3. Если `p.py` классифицировал файл иначе (например `UNKNOWN`, хотя график есть) — укажи на это и на строку в `p.py`, где классификация ошибается.
4. Ответ — коротко по-русски: вердикт, 2–3 улики из файла (с цитатами), и простыми словами — почему такое бывает (частота запросов, headless-детект, cookie сессии Incapsula) и что можно попробовать. Код не меняй без просьбы.
